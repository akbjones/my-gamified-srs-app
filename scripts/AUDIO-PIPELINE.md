# Audio pipeline

End-to-end how card audio gets from text → played in the browser.

## Generation (offline, run once per language)

For each language, run the generation script. It reads `src/data/<lang>/deck.json`,
hits the TTS API for each card's `target` text, and writes MP3 files to
`public/quest-audio/<prefix>-<id>.mp3`.

| Language | Script                          | Voice                       |
|----------|---------------------------------|-----------------------------|
| 10 langs | `generate-audio.cjs --lang=XX`  | `<lang>-Chirp3-HD-Aoede`    |
| Welsh    | `regen-welsh-inconsistent.py`   | `cy-GB-NiaNeural` via Edge TTS |

See `CANONICAL-VOICES.md` for the per-language voice table and rationale.

To bulk-regenerate everything non-Welsh:

```bash
GOOGLE_TTS_KEY=$YOUR_KEY node scripts/regen-all-langs-chirp.cjs --concurrency=3
```

The script handles 429 rate limits with exponential backoff (1s, 2s, 4s,
8s, 16s, 32s) and persists `/tmp/regen-<lang>-done.json` so it can be
safely resumed with `--resume`.

## Storage

MP3s live in `public/quest-audio/` and are served at `/quest-audio/<file>`
by Vite during dev and by Cloudflare Pages in prod. The path is
configurable via `VITE_AUDIO_BASE_URL` (e.g. point at Cloudflare R2 if
the deck size makes Pages prohibitive).

### Cloudflare R2 prod setup

- Bucket: `langlab-srs-audio` (NOT `langlab-audio` — that's an old bucket
  that's not served by the public URL)
- Key prefix: `quest-audio/<filename>`
- Public URL: `https://pub-fa9d7e83944246fcb9a03f217e1dd0c9.r2.dev/quest-audio/<filename>`
- **CORS is required**. Without it, `fetch()` from the app fails silently
  and the audio service falls through to iOS's robotic system TTS — which
  is what users hear as "old voices coming back". Set CORS via:
  ```bash
  curl -X PUT \
    -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{"rules":[{"allowed":{"origins":["*"],"methods":["GET","HEAD"],"headers":["*"]},"exposeHeaders":["Content-Length","ETag","Content-Type"],"maxAgeSeconds":3600}]}' \
    "https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID/r2/buckets/langlab-srs-audio/cors"
  ```
  Verify with `curl -I -H "Origin: https://langlab-srs.netlify.app" -X OPTIONS <audio-url>` — should return 204 with `Access-Control-Allow-Origin: *`.

## Playback (`src/services/audioService.ts`)

Three-tier fallback chain:

1. **Pre-recorded MP3** (default, instant)
   - `fetchAndCacheMp3()` fetches the file, makes a blob URL, caches it.
   - 24-entry LRU cache so going backwards or rapidly switching cards
     doesn't re-fetch.
   - Preload tier: `preloadCardAudio()` is called by `StudySession` and
     `ListenMode` for the **next 2 cards** when a card displays, so
     playback on the next card is instant.

2. **Google Cloud TTS** (live API, paid)
   - Fires only when (a) `googleApiKey` is configured AND (b) the MP3
     fetch failed for an unexpected reason. Uses the same Chirp3-HD-Aoede
     voice as the offline generation, so it sounds identical.
   - 200-entry blob cache (`ttsCache`) keyed by lang/speed/text.

3. **Browser TTS** (last resort, free, robotic)
   - Used when both MP3 and Google TTS are unavailable. Picks whatever
     voice the browser provides for the language — quality varies wildly.
   - Welsh has no premium Google option, so the fallback chain skips
     step 2 and goes straight to step 3 if the MP3 fails.

## Token-based race protection

`playToken` is a monotonic counter incremented on every `playCardAudio`
call. Each call captures its token at the start; whenever it would do
something visible (start playback, write to `currentAudio`), it first
checks `myToken !== playToken` and bails if a newer call has come in.

This handles:
- Rapid card switching (user clicks Next while previous card is loading)
- ListenMode mid-autoplay user interaction
- Race between the manual Replay button and auto-play `useEffect`

## What changed (history)

- **Welsh voice bug** (2026-06-11): the Welsh deck had been generated by
  ≥3 different scripts using different voices (espeak-ng robot voice,
  Azure NiaNeural direct API, Edge TTS NiaNeural). User reported audio
  alternating male/female. Fixed by regenerating the 1,082 non-canonical
  files via Edge TTS NiaNeural (free, same voice as the bulk).
- **Audio lag** (2026-06-11): every card change triggered a fresh fetch
  with a 350ms retry penalty. Added blob cache + preloader for the next
  2 cards. Playback now instant after the first card.
- **Voice tier upgrade** (2026-06-11): 10 non-Welsh languages bumped
  from Google Wavenet to Chirp3-HD-Aoede (Google's highest quality tier,
  same female voice across all languages for consistency).

## Auditing

To verify all audio for a language uses one voice, check encoder
signatures (each TTS provider/tier produces a distinct MP3 frame header):

```bash
node -e "
const fs=require('fs'),path=require('path'),dir='public/quest-audio';
const all=fs.readdirSync(dir).filter(f=>f.startsWith('es-')&&f.endsWith('.mp3'));
const sigs=new Map();
for(const f of all){const b=fs.readFileSync(path.join(dir,f));if(b[0]===0xff&&(b[1]&0xe0)===0xe0)sigs.set(b[2],(sigs.get(b[2])||0)+1)}
for(const[s,n] of sigs)console.log('0x'+s.toString(16),n);"
```

A healthy language has ONE signature (e.g. all 0x44 = Chirp3-HD). Welsh
has TWO because the bulk uses Azure's direct API encoder (0x80) and the
regen uses Edge TTS's encoder (0x64) — same voice, different bitrates.
